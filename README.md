# db-exp（マスキング出力ツール）

**データベース**（Oracle / PostgreSQL）と**ドキュメント**（Excel・CSV・テキスト・Markdown）から、
日本の業務システムでマスキング（脱敏）が必要な項目を**自動で判定**し、マスクして出力する Web アプリケーションです。
単一の exe ファイルとして配布でき、ダブルクリックするとブラウザで画面が開きます。

```
入力                         判定                                  出力
─────────────────────      ─────────────────────────────         ──────────────────────────────
データベース                 ┌ マスキング対象（自動判定）   ┐        Excel（.xlsx）
  Oracle / PostgreSQL   →   │   規則を確認・変更できる     │   →   マスク済みダンプ（INSERT 文）
                             │                              │        マスキング用 UPDATE 文
ドキュメント                 └ 要確認（人が判断）           ┘
  xlsx / csv / txt / md →       1 件ずつ「マスクする / しない」   →   Markdown（ZIP）
```

- 判定は**PC 上の規則と辞書だけ**で行い、データを外部のサービス（AI 等）に送信しません。
- 画面: React + shadcn/ui ／ サーバー: FastAPI（ローカル PC 上で `127.0.0.1` のみで待ち受け）
- 配布形態: PyInstaller による単一 exe（`db-exp.exe`）

## 主な機能

### 自動判定（マスキング対象一覧・要確認一覧）

| 機能 | 内容 |
| --- | --- |
| 列の判定 | 列名・論理名（コメント）・データ型・**先頭の値の形式**から、氏名・住所・電話番号・メール・郵便番号・生年月日・マイナンバー・カード番号・口座番号・パスワード・要配慮個人情報などを判定 |
| 値の検査 | マイナンバーの**検査用数字**、カード番号の **Luhn 検査**、都道府県名、**よくある姓の辞典**、カナ氏名などで値そのものも確認（列名が `COL7` でも中身がメールアドレスなら検出） |
| 誤検出の抑止 | `TEL_KBN`（電話区分）・`メール配信フラグ`・`商品名`・`会社名` などは対象外。列名と値が矛盾する列は要確認に回す |
| 文中の検出 | 文章や備考欄の中の `氏名：山田太郎`、`山田様`、`TEL 03-…`、`〒100-0001`、住所、メールアドレス等を検出 |
| 2 つの一覧 | 確度の高いものは「**マスキング対象**」（推奨規則を自動設定）、判断が必要なもの（確度が低い・顧客番号・性別・年収・主キー等）は「**要確認**」として人が 1 件ずつ判断 |
| 判定結果一覧 | 判定理由・処理内容・件数・マスク後の例を Excel で保存（**元の値は記載しない**ため、そのまま共有・保管できる） |

判定ルールの詳細は [docs/マスキング仕様.md](docs/マスキング仕様.md) を参照してください。

### データベース

| 機能 | 内容 |
| --- | --- |
| 接続管理 | Oracle（サービス名 / SID / TNS・接続文字列）、PostgreSQL の接続情報を保存。接続テスト可能 |
| 読み取り専用接続 | Oracle は `SET TRANSACTION READ ONLY`、PostgreSQL は読み取り専用セッションで接続。データを更新しません |
| 一括スキャン | スキーマ内の表（検索で絞り込んだ表）をまとめて判定し、結果をエクスポートリストに一括反映 |
| テーブル選択 | スキーマ切替、表・ビュー・マテビューの一覧、**表名・論理名（コメント）で検索**（全角/半角を区別しない） |
| 列選択 | 出力列のチェック、列コメントを論理名として表示、主キー表示、見出しの任意変更、判定結果の表示 |
| マスキング | 氏名・住所・電話番号・メール・郵便番号・生年月日など**日本のデータ形式に合わせた規則**を列ごとに設定。備考欄は文中の個人情報だけを伏せられる |
| 抽出条件 | WHERE 句・ORDER BY 句・最大件数を指定可能 |
| プレビュー | マスキング適用後のデータを先頭 50 件表示 |
| **出力形式** | **Excel** / **マスク済みダンプ（INSERT 文）** / **マスキング用 UPDATE 文** から選択 |
| Excel 書式 | 日本語フォント（游ゴシック等）、全角幅を考慮した列幅、見出し固定、オートフィルタ、日付書式 `yyyy/mm/dd`、複数テーブルをシート別に出力 |
| INSERT 文 | マスク済みデータをテスト環境に投入できる SQL。COMMIT 間隔・DELETE 文の付与・出力先スキーマ名・文字コード（UTF-8 / Shift_JIS）を指定可能 |
| UPDATE 文 | 本番データをコピーした**テスト環境で実行し、その場でマスク**する SQL（データは含まない）。マスク結果は INSERT 文と同じ |
| 型への対応 | 数値・日付型の列、NOT NULL 列、主キー、列の最大長（BYTE / CHAR）に合わせて値を調整し、内容を SQL 内にコメントで記録 |
| 大量データ | ストリーミング出力でメモリを圧迫しない。Excel は 1,048,576 行を超えるとシートを自動分割 |
| 監査用情報 | Excel は「エクスポート情報」シート、SQL はファイル先頭のコメントに出力日時・接続先・件数・条件・マスキング内容を記録 |
| 設定の保存 | エクスポートリストと出力オプションを JSON で保存・再読込（定型作業の再実行に） |

### ドキュメント

| 機能 | 内容 |
| --- | --- |
| 対応形式 | Excel（.xlsx / .xlsm）、CSV / TSV、テキスト（.txt / .log）、Markdown（.md） |
| 読み込み | ファイル・**フォルダごと**の選択、ドラッグ＆ドロップ。文字コード（UTF-8 / Shift_JIS / EUC-JP）は自動判定 |
| 表の判定 | CSV、Excel の見出し行付きの範囲、Markdown の表は**列ごと**に判定 |
| 文章の判定 | それ以外の文章（Excel の方眼紙・メモ・議事録など）は**文中の語句ごと**に判定 |
| 出力 | ファイルごとのマスク済み **Markdown**（フォルダ構成を保持）と「マスキング結果一覧.md」を ZIP で出力 |

## 使い方（exe 版）

1. `db-exp.exe` をダブルクリックします。コンソール画面が開き、続いて既定のブラウザで画面が開きます。
   - ブラウザが開かない場合は、コンソールに表示された URL（例: `http://127.0.0.1:8765/`）を開いてください。
2. 画面上部で「**データベース**」か「**ドキュメント**」を選びます。
3. 終了するときはコンソール画面を閉じてください。

### データベース

1. 左上の「接続先」→「新規」で接続情報を登録し、「接続」を押します。
2. スキーマを選びます。
3. **まとめて判定する場合**: 「一括スキャン」を押します（検索欄で表を絞り込んでからでも可）。
   - 「マスキング対象」タブで推奨規則を確認し、必要なら変更・除外します。
   - 「要確認」タブで、値の例と判定理由を見ながら 1 件ずつ「マスクする / しない」を選びます。
   - すべて判断したら「判定結果をエクスポートリストに反映」を押します。
4. **表ごとに設定する場合**: テーブルをクリックし、列ごとの出力・マスキング規則・抽出条件を設定して「エクスポートリストに追加」を押します。
   - 自動判定でマスキング対象となった列には規則が自動で設定され、要確認の列には「要確認」の印が付きます（印にマウスを重ねると判定理由を表示）。
5. 右側の「出力形式」を選び、出力します。完了すると自動でダウンロードされます。
   - **Excel**: 見出し形式・フォントを選べます。
   - **マスク済みダンプ（INSERT 文）**: テスト環境で実行すると、マスク済みのデータが投入されます。
   - **マスキング用 UPDATE 文**: **本番データをコピーしたテスト環境**で実行すると、表の全行をその場でマスクします。**本番環境では実行しないでください。**

```bash
# 実行例（Oracle）
sqlplus user/pass@host/service @顧客マスタ_マスキング用UPDATE_20250401_120000.sql
# 実行例（PostgreSQL）
psql -h host -U user -d db -v ON_ERROR_STOP=1 -f 顧客マスタ_20250401_120000.sql
```

### ドキュメント

1. 左側にファイルまたはフォルダをドロップするか、「ファイル選択」「フォルダ選択」で読み込みます。読み込むと自動で判定します。
2. 「マスキング対象」「要確認」タブで内容を確認・判断します（DB と同じ操作）。
   - 要確認は同じ語句ごとに 1 件にまとまっており、判断はそのファイル内の同じ語句すべてに適用されます。
3. 「Markdown で出力（ZIP）」を押すと、マスク済みの Markdown と「マスキング結果一覧.md」が ZIP でダウンロードされます。
   - ファイルを追加・削除すると再判定します（判断済みの内容は引き継ぎます）。

### 起動オプション

```
db-exp.exe --port 9000      待ち受けポートを指定（既定 8765。使用中なら自動で空きポートを使用）
db-exp.exe --no-browser     ブラウザを自動で開かない
```

## 設定・保存データ

保存先は `%APPDATA%\db-exp`（Windows）または `~/.db-exp`（Linux/macOS）です。
環境変数 `DBEXP_DATA_DIR` で変更できます。

| ファイル | 内容 |
| --- | --- |
| `connections.json` | 接続情報。パスワードは「パスワードを保存する」を選んだ場合のみ保存 |
| `settings.json` | 任意の設定ファイル（下記） |
| `exports\` | 生成した Excel・SQL の一時保存先。既定で 6 時間後に自動削除 |
| `uploads\` | 読み込んだドキュメントの一時保存先。既定で 6 時間後に自動削除（「クリア」で即時削除） |

### settings.json（任意）

```json
{
  "oracle_client_lib_dir": "C:\\oracle\\instantclient_19_20",
  "port": 8765,
  "export_retention_seconds": 21600
}
```

| キー | 説明 |
| --- | --- |
| `oracle_client_lib_dir` | Oracle Instant Client のフォルダ。指定すると **Thick モード**で接続（下記参照）。環境変数 `DBEXP_ORACLE_CLIENT_DIR` でも指定可 |
| `port` | 既定の待ち受けポート。環境変数 `DBEXP_PORT` でも指定可 |
| `export_retention_seconds` | エクスポートファイル・読み込んだドキュメントの保持時間（秒） |

### Oracle の接続モードについて

- 既定は python-oracledb の **Thin モード**で、Oracle Client のインストールは不要です（対応: Oracle Database 12.1 以降）。
- **Oracle 11g 以前**に接続する場合や、Thin モード非対応の機能（一部の認証方式など）が必要な場合は、
  [Oracle Instant Client](https://www.oracle.com/jp/database/technologies/instant-client.html) を配置し、
  `oracle_client_lib_dir` を設定して Thick モードを使用してください。

### 日本語データについて

- Thin モードでは常に UTF-8 でデータを受信し、DB 側の文字コード（`JA16SJIS`、`JA16SJISTILDE`、`JA16EUC`、`AL32UTF8` 等）からの変換は DB サーバーが行います。追加設定は不要です。
- PostgreSQL は `client_encoding=UTF8` で接続します。
- 波ダッシュ（〜 / ～）、丸数字（①）、髙・𠮷 などの外字・異体字もそのまま出力されます。ただし DB 側の文字コードに存在しない文字は、格納時点で置換されている場合があります。
- `timestamp with time zone` 型は、PC のローカル時刻（日本では JST）に変換して出力します。

## セキュリティに関する注意

- サーバーは `127.0.0.1` のみで待ち受け、他の PC からは接続できません。
- 他サイトからの不正なリクエスト（CSRF・DNS リバインディング）を防ぐため、Host ヘッダーと独自ヘッダーを検証しています。
- 接続は読み取り専用です。さらに WHERE / ORDER BY 欄では `;`、コメント、更新系キーワードを拒否します。
- 「パスワードを保存する」を選ぶと、パスワードは**暗号化されず簡易的な難読化のみ**でユーザーフォルダに保存されます。共用 PC では保存しないでください。
- マスキングは**出力するファイルにのみ**適用され、DB・元のファイルは変更しません。
  例外は「マスキング用 UPDATE 文」で、これは**利用者がテスト環境で実行する**ためのファイルです（ツール自体は DB を更新しません）。
- 自動判定・判定結果の画面表示はすべて PC 内で行い、データを外部に送信しません。要確認の判断のため、画面には元の値の例（各 3 件まで）を表示します。
- 判定結果一覧（Excel・Markdown）には元の値を記載しません。UPDATE 文にはハッシュ用ソルトが含まれます。
- 自動判定は列名・論理名・値の形式による推定です。**出力前に必ず一覧・プレビューで確認してください。**

## ビルド方法

### 必要なもの

- Node.js 20 以上
- Python 3.10 以上

### Windows 用 exe の作成

PyInstaller はクロスコンパイルに対応していないため、**Windows 上で**実行してください。

```bat
scripts\build.bat
```

`dist\db-exp.exe` が生成されます（約 35MB）。この 1 ファイルを配布すれば動作します。

### Linux / macOS

```bash
./scripts/build.sh
```

`dist/db-exp` が生成されます。

### 手動でビルドする場合

```bash
# 1. フロントエンド
cd frontend
npm ci
npm run build          # frontend/dist が生成される

# 2. バックエンド＋exe
cd ../backend
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt    # Linux/macOS は .venv/bin/pip
.venv/Scripts/pyinstaller --noconfirm db_exp.spec    # backend/dist/db-exp(.exe) が生成される
```
