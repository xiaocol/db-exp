# マスキング仕様

マスキングは列単位（ドキュメントの文章は語句単位）で設定し、出力の直前に適用されます。元の DB・ファイルは変更しません
（「マスキング用 UPDATE 文」を除く。後述）。
実装は `backend/app/masking.py`（規則）、`backend/app/detector.py`・`textscan.py`（自動判定）、`backend/app/sqlgen.py`（SQL 出力）です。

## 共通ルール

- **NULL は NULL のまま**出力します（値が無いこと自体は秘匿情報ではないため）。
- 伏せ字は、**全角文字は全角「＊」、半角文字は半角「*」**で置き換え、見た目の桁数を保ちます。
- 空白（半角・全角スペース）は伏せずに残します。
- 数値・日付の列に文字列系の規則を適用した場合、文字列に変換してからマスキングします（日付は `yyyy/mm/dd` 形式）。
- マスキングした列は、Excel の見出しセルが**オレンジ色**になります。

| --- | --- | --- | --- |

| メールアドレス | `email` | `taro@example.co.jp` → `t***@example.co.jp` | — |
| 数字のみマスク | `digits` | `03-1234-5678` → `**-****-5678` | 先頭に残す桁数、末尾に残す桁数（既定 4） |

### 各規則の詳細

**氏名（`name`）**
- 半角・全角スペースで区切られている場合、最初の区切りより前（姓）を残し、以降を伏せます。
  - `山田 太郎` → `山田 ＊＊`、`ヤマダ　タロウ` → `ヤマダ　＊＊＊`
- 区切りが無い場合は先頭 1 文字のみ残します。`山田太郎` → `山＊＊＊`
- カナ氏名・英字氏名にも使用できます。

**ダミー氏名（`fake_name`）**
- 元の値と「ハッシュ用ソルト」から決定的に選ぶため、**同じ人物は常に同じダミー氏名**になります。
- 候補は 20 姓 × 20 名 = 400 通りのため、別人が同じ名前になることがあります。突合せキーには `hash` を使用してください。

**数字のみマスク（`digits`）**
- 数字（全角数字を含む）のみを伏せ、ハイフン・括弧・空白などの区切り文字は残します。
  - `090(1234)5678` → `***(****)5678`
  - `０３－１２３４－５６７８` → `＊＊－＊＊＊＊－５６７８`
- 数字の桁数が「残す桁数」の合計以下の場合は、情報漏えい防止のため**すべて伏せます**。
- 電話番号・FAX・携帯番号、カード番号、口座番号などに使用します。

**住所（`address`）**
- 都道府県＋市区町村までを残し、町名・番地・建物名を `＊＊＊＊` に置き換えます。
- 政令指定都市の区（`横浜市中区`）、郡（`北佐久郡軽井沢町`）にも対応しています。
- 先頭に郵便番号（`〒100-0005 ` 等）がある場合は、郵便番号の下 4 桁も伏せます。
- 住所として解釈できない値は、先頭 3 文字のみ残します。
- 市区町村の判定は文字パターンによるため、`四日市市` のように地名に「市」を含む場合など、まれに残す範囲が短くなることがあります（伏せる側に倒れるため情報漏えいにはなりません）。

**日付（`date_year`）**
- 日付型は年のみ残して `1985/**/**` とします（SQL 出力では年初日 `1985-01-01` にします。後述）。
- 文字列の場合、先頭の西暦 4 桁（全角可）を残し、以降の数字だけを伏せます。区切り文字と桁数は保ちます。
  - `1985/04/01` → `1985/**/**`、`19850401` → `1985****`、`１９８５年４月１日` → `１９８５年＊月＊日`
- 和暦（`昭和60年4月1日`）は `昭和60年＊＊月＊＊日` とします。

**数値の丸め（`round_number`）**
- 指定した桁で**四捨五入**します（SQL の `ROUND` と同じ結果になるよう、銀行丸めは使いません）。

**ハッシュ化（`hash`）**
- `SHA-256(ソルト + 値)` の先頭 N 桁（16 進）を出力します。
- 同じソルトなら同じ値は同じハッシュになるため、**テーブル間の突合せキー**として使えます。
- ソルトを指定しない場合、電話番号など候補の少ない値は総当たりで推測される可能性があります。社外に渡す場合はソルトを指定してください（ソルトは Excel やエクスポート情報シートには出力されません。**UPDATE 文にはソルトが含まれます**）。

**文中の個人情報のみマスク（`text_pii`）**
- 備考欄・メモ欄など自由記述の列に使います。文章全体は残し、文中で検出した氏名・電話番号・メールアドレス・住所・郵便番号・マイナンバー等だけを、種類ごとの既定規則で伏せます。
- 検出方法は「自動判定 ― 文中の検出」と同じです。「確度の高いものだけ」にすると、要確認相当のもの（`123-4567` など）は伏せません。

## 自動判定

外部のサービスには送信せず、PC 上の規則と辞書だけで判定します。判定結果は次の 2 つの一覧に分かれます。

| 一覧 | 条件 | 扱い |
| --- | --- | --- |
| **マスキング対象（自動判定）** | 確からしさ 70% 以上 | 推奨規則が初期設定される。確認のうえ規則の変更・除外ができる |
| **要確認（人が判断）** | 確からしさ 35〜69%、または業務判断が必要な種類 | 人が 1 件ずつ「マスクする / しない」を選ぶ。**すべて判断するまで出力できない** |

### 列の判定（DB の列・ドキュメントの表の列）

次の根拠を合成して確からしさを算出します。

1. **列名・論理名（コメント）** … 「氏名」「TEL_NO」「JUSHO」のような語は強い根拠（85%）、「〇〇名」「NAME」「連絡先」のような語は弱い根拠（45%）。
   物理名は `custName` → `CUST_NAME` のように単語に分けて照合します（`MEISAI` の中の `MEI` などには反応しません）。
2. **値の形式**（DB は先頭 200 件、ドキュメントは先頭 500 行）… 一致率 × 種類ごとの重み。
   - 電話番号（0 始まり 10〜11 桁、区切りの有無）、郵便番号（`123-4567`）、メールアドレス
   - マイナンバー（12 桁＋**検査用数字の検証**）、クレジットカード番号（**Luhn 検査**）
   - 住所（都道府県名から始まる／市区町村＋番地）、氏名（**よくある姓 約 200 件の辞典**、姓＋空白＋名、カナ氏名）
3. **減点**
   - 「区分」「フラグ」「_KBN」「_FLG」「コード」などを含む列（`TEL_KBN`、`メール配信フラグ`）は値そのものが個人情報ではないため大きく減点。
   - 「商品名」「会社名」「PRODUCT_NAME」など、人以外の「名」は氏名の対象外。
   - 列名は該当するのに値の形式がまったく合わない場合（`TEL` 列に `1`,`2`…）は要確認に下げる。
   - 文字列でしか格納されない種類（氏名・メール等）が数値・日付型の列に付いている場合は減点。
4. **常に要確認にするもの**
   - 主キーの列（マスクすると一意性や他表との突合せに影響するため）
   - 判定の候補が拮抗している列
   - 業務判断が必要な種類（下表の「要確認」）

| 種類 | 既定の規則 | 主な列名・論理名 | 値による判定 | 扱い |
| --- | --- | --- | --- | --- |
| パスワード・暗証番号 | 空欄（NULL） | パスワード、暗証、PWD、PIN、CVV、セキュリティコード | — | 自動 |
| マイナンバー | 全桁マスク | マイナンバー、個人番号、MY_NUMBER、KOJIN_NO | 検査用数字 | 自動 |
| 公的な証明書番号 | 全桁マスク | 免許証、旅券、パスポート、保険証、基礎年金番号、在留カード | — | 自動 |
| クレジットカード番号 | 数字のみ（末尾 4 桁） | カード番号、CARD_NO、CREDIT | Luhn 検査 | 自動 |
| 口座番号 | 数字のみ（すべて） | 口座番号、KOZA_NO、ACCOUNT_NO | — | 自動 |
| メールアドレス | メールアドレス | メール、MAIL、EMAIL | 形式 | 自動 |
| 電話番号 | 数字のみ（末尾 4 桁） | 電話、携帯、TEL、FAX、PHONE、DENWA、KEITAI | 形式 | 自動 |
| 郵便番号 | 郵便番号 | 郵便、〒、ZIP、POST_CD、YUBIN | 形式 | 自動 |
| 住所 | 住所 | 住所、所在地、送付先、ADDR、JUSHO | 都道府県・番地 | 自動 |
| 生年月日 | 日付（年のみ） | 生年月日、誕生日、BIRTH、DOB、SEINENGAPPI | 日付であること | 自動 |
| 氏名 | 氏名 | 氏名、名前、フリガナ、〇〇者名、宛名、名義、SHIMEI、SEI、MEI、CUST_NAME | 姓の辞典・カナ氏名 | 自動 |
| 要配慮個人情報 | 全桁マスク | 病歴、病名、診断、障害、国籍、本籍、宗教、犯罪、血液型 | — | 自動 |
| 自由記述（備考等） | 文中のみマスク | 備考、メモ、コメント、摘要、問合せ内容、BIKO、NOTE、REMARKS | 文中の個人情報 | 文中に見つかれば自動、なければ要確認 |
| 個人を識別する ID | ハッシュ化 | 顧客番号、社員番号、会員ID、ログインID、CUST_ID、SHAIN_NO | — | 要確認 |
| 性別 | 全桁マスク | 性別、SEX、GENDER、SEIBETSU | — | 要確認 |
| 年齢 | 数値の丸め（十の位） | 年齢、AGE、NENREI | — | 要確認 |
| 年収・給与等 | 数値の丸め（千の位） | 年収、給与、賞与、所得、SALARY、NENSHU | — | 要確認 |
| IP アドレス | 全桁マスク | IPアドレス、IP_ADDR、CLIENT_IP | IPv4 形式 | 要確認 |

列名がどの種類にも当たらなくても、値の形式（メールアドレス・カード番号など）だけで判定されることがあります。

### 文中の検出（ドキュメントの文章・備考欄）

| 検出するもの | 例 | 扱い |
| --- | --- | --- |
| 項目名と値の組 | `氏名：山田 太郎`、`TEL 03-1234-5678`、`住所：…`、`生年月日：…` | 自動（値の部分のみ伏せる） |
| メールアドレス | `taro@example.com` | 自動 |
| 区切り付きの電話番号 | `03-1234-5678`、`(03)1234-5678`、`+81-90-…` | 自動 |
| 〒付きの郵便番号 | `〒100-0001` | 自動 |
| マイナンバー・カード番号 | 検査用数字・Luhn が一致する 12 桁・14〜16 桁 | 自動 |
| 都道府県から始まる番地付きの住所 | `東京都千代田区丸の内1-1-1` | 自動 |
| 敬称付きの氏名（よくある姓） | `山田様`、`田中さん` | 自動（敬称は残す） |
| 敬称付きのその他の語・カタカナ | `カトウ様` | 要確認 |
| 区切りなし 10〜11 桁の数字 | `0312345678`（注文番号の可能性） | 要確認（直前に `TEL` 等があれば自動） |
| 「3 桁-4 桁」の数字 | `123-4567`（受付番号の可能性） | 要確認 |
| 姓＋空白＋名 | `佐藤 花子` | 要確認 |
| 番地のない地名 | `大阪府大阪市` | 要確認 |

- 「お客様」「皆様」「ご担当者様」「各位」など、敬称の前が人名でない語は検出しません。「担当：営業部」のような会社・部署名も対象外です。
- ドキュメントの要確認は**同じ語句ごとに 1 件**にまとめ、判断はファイル内の同じ語句すべてに適用します。自動判定はファイル×種類ごとに 1 件にまとめます。
- ドキュメントの表（CSV 全体、Excel の見出し行付きの範囲、Markdown の表）は列ごとに判定し、マスキング対象にならなかった列のセルは文中の検出を行います。

**自動判定は推定です。** 出力前に必ず一覧・プレビューで確認してください。判定ルールは `backend/app/categories.py`（種類・列名のパターン・値の検査）と
`backend/app/textscan.py`（文中の検出）で変更できます。

## SQL 出力での扱い

「マスク済みダンプ（INSERT 文）」は Excel と同じマスク関数を Python 側で適用します。「マスキング用 UPDATE 文」は同じ規則を
DB の関数（`REGEXP_REPLACE`、`SUBSTR`、`STANDARD_HASH` / `sha256` 等）で表現し、テスト環境の DB 上でその場でマスクします。
両者の結果は、下記の例外を除いて一致します（Oracle・PostgreSQL の実 DB で確認済み）。

### 列の型に合わない規則

数値型・日付型の列には文字列のマスク結果（`****` など）を格納できないため、次のように置き換え、SQL ファイル内にコメントで記録します。

| 列の型 | 規則 | SQL 出力での扱い |
| --- | --- | --- |
| 文字列 | すべて | 規則どおり。列の最大長（Oracle の BYTE 指定はバイト数）を超える場合は切り詰める |
| 数値 | 数値の丸め / 固定値（数値） | 規則どおり |
| 数値 | ハッシュ化 | ハッシュ値を列の桁数に収まる数値にする（同じ値は同じ数値。別の値が同じ数値になることもある） |
| 日付 | 日付（年のみ残す） | 年初日（1 月 1 日）に切り捨て |
| 数値・日付 | その他 | NULL（NOT NULL 列なら 0 / 年初日） |
| 主キー | 型に合わない規則 | **変更しない**（一意制約違反を防ぐため。⚠ 付きのコメントで記録） |
| 文字列（NOT NULL） | 空欄（NULL） | `＊` |
| CLOB | ハッシュ化・ダミー氏名 | 全桁マスク |

### UPDATE 文の注意

- **本番環境では実行しないでください。** 本番データをコピーしたテスト環境で、表の**全行**を書き換えます（抽出条件・最大件数は適用されません）。
- 「出力」のチェックを外した列は UPDATE されず、元の値のまま残ります。
- 「文中の個人情報のみマスク」は DB の正規表現で表現できる範囲の**簡易版**です（メールアドレス・区切り付き電話番号・〒付き郵便番号・10 桁以上の数字・敬称の前の漢字）。
  敬称の前の語は「お客様」なども含めて伏せます。厳密に行う場合は INSERT 文（ダンプ）を使ってください。
- ハッシュ化・ダミー氏名は Oracle 12c 以降（`STANDARD_HASH`）、PostgreSQL 11 以降（`sha256`）が必要です。
  DB の文字コードが UTF-8 以外（JA16SJIS 等）の場合、ハッシュ値は INSERT 文・Excel と一致しません（同じ値は同じハッシュになる性質は保たれます）。
- Oracle 用のスクリプトは SQL*Plus / SQLcl / SQL Developer の `SET DEFINE OFF`・`WHENEVER SQLERROR EXIT ROLLBACK` を含みます。
  PostgreSQL 用は全体を `BEGIN` 〜 `COMMIT` で囲みます（`psql -v ON_ERROR_STOP=1 -f` で実行してください）。

## 規則の追加方法

1. `backend/app/masking.py` にマスク関数 `def _xxx(value, params) -> Any` を追加する。
2. `_SIMPLE_RULES`（ソルトを使う場合は `_SALTED_RULES`）に登録する。
3. `RULE_DEFINITIONS` に表示名・例・パラメータ定義を追加する（画面の選択肢は自動で反映されます）。
4. `backend/tests/test_masking.py` にテストを追加する。
